# Privacy

Medical records are highly sensitive. These rules apply to the repository
itself as well as to any implementation.

## Data in the repository

- The repository **must** contain only synthetic data (e.g. generated by a
  tool such as Synthea) or public datasets that are explicitly
  de-identified and licensed for reuse. Never real patient data.
- This applies to source code, test fixtures, sample files, screenshots,
  documentation, issues and PR descriptions.
- Every bundled dataset **must** state where it came from and its license,
  in a README next to it.
- Data that's synthetic but realistic-looking **should** be marked as
  synthetic where a viewer sees it (e.g. in the file name or a visible
  label), so it can't be mistaken for a real record.

## Sample data

- The repository starts with a small set of fake records, written by hand
  for this project and committed to the repo. Tests and demos use this
  set.
- This data **must not** be copied or derived from any third-party
  dataset, so it carries no outside license terms. Its README states that
  it was written for this project and is covered by the repository's
  MIT license.
- Generating larger datasets with a tool is out of scope for now. If it's
  needed later, specify it in its own document.

## Fixtures that mimic a real source

Parsing a source like 1177 needs fixtures that look like the real pages.
Real records may be used to learn what a page looks like, but never as
the content of a fixture.

- A fixture **may** reproduce the structure of a real page: its
  elements, attributes, headings, section names and layout.
- All content in a fixture **must** be invented: names, dates, care
  units, codes chosen for the fixture, values, and every word of free
  text. Nothing is copied from a real record, not even after
  "anonymizing" it.
- Why: free text in medical records identifies people in ways that are
  easy to miss (relatives, places, unusual events), and a combination of
  dates, diagnoses and care units can identify a person even with the
  name removed. Removing identifiers from real text isn't reliable
  enough. Writing new content is.
- Personnummer in fixtures **must** be official test personnummer
  published by Skatteverket, never one made up at random, which could
  belong to a real person.
- Fixture files **must** be marked as synthetic in their file name, in
  line with the rule above.

## Real records on the developer's machine

- Real records used during development **should** be kept outside the
  repository's folder entirely, so they can't be committed by accident.
  The repository's ignore rules for real data are a safety net, not the
  plan.

## Public knowledge vs. personal data

- Reference data that contains no personal data, such as code lists,
  abbreviation lists and plain-language explanations of medical terms,
  **may** be produced with any tool, including cloud services, and
  committed to the repository once reviewed. Its README states where it
  came from.
- Record data, and anything derived from a particular patient's records,
  is personal data and follows the rules below.

## Data handling in the app

- Records a user loads **must** stay on their device by default. Nothing is
  uploaded, logged remotely or sent to analytics.
- Any feature that sends record data off the device (e.g. to an external
  API) **must** be specified in its own document first, and **must** be
  clearly disclosed to the user before any data leaves.
- The app **must not** make any outgoing network request while running,
  unless that request is specified in its own document. This makes
  "stays on the device" something that can be tested, not just intended.
- The app **must not** load anything from outside the device at runtime:
  no analytics, telemetry, external fonts or externally hosted code.
- Logs and error messages **must not** include record contents.
